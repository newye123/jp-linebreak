# 案例索引

三个案例都来自同一件事：**一个看起来在工作的排版工具，实际没在工作。**

按「你现在的症状」找：

| 你看到的现象 | 看哪份 | 一句话 |
|---|---|---|
| 有测试文件，跑起来全绿，但线上排版是错的 | [01](01-four-cases-zero-assertions.md) | 四条用例，零条断言；退出码只证明脚本没崩 |
| 同一个按钮，有时候结果不一样，用户没发现 | [02](02-one-button-three-implementations.md) | 三条代码路径各自决定怎么切，降级路径静默生效 |
| 界面显示了一个数字/结论，但没人知道它哪来的 | [03](03-fabricated-confidence.md) | `confidence \|\| 0.8`，缺失被填成了常量 |

## 三份的共同点

- **没有一个案例是「崩溃」。** 三个都是退出码 0、HTTP 200、界面正常。
- **三份都能用一条命令复现。** 每份的「取证」节里是真实终端输出，不是回忆。
- **三份的修法都不是加判断，是改结构。** 01 把打印改成断言，02 把三份实现合成一份，03 把默认值改成 `null`。

## 三份的差别

- 01 是**检查器失灵**（工具本身不报警）
- 02 是**实现分叉**（同一个概念有多种实现）
- 03 是**数据伪造**（缺失被填成值）

这三类故障的排查手法不一样：01 靠负控（故意注入破坏，看它红不红），02 靠 diff（主路径关掉，跑同一批输入），03 靠问句（这个字段缺失时应该是什么）。
